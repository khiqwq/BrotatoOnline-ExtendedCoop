## 4. 性能预算（R17，提议值）

参考硬件即本机（见第 6 节）。测量场景：8 人、Abyssal Terrors 启用、第 15～20 波常规敌潮、1920×1080、默认画质，每次至少 3 分钟。

| 指标 | 预算 |
| ---- | ---- |
| Host 帧时间 | 平均 ≤ 16.7 ms，P95 ≤ 33.3 ms |
| Client 帧时间 | 平均 ≤ 16.7 ms，P95 ≤ 33.3 ms |
| 扩展自身逐帧处理（消息处理 + 槽位/阶段检查） | P95 ≤ 2 ms |
| Host 上行带宽 | 峰值 ≤ 2 Mbit/s，平均 ≤ 1 Mbit/s（与四人基线同条件对比，增长需在报告中解释） |
| 单个可靠消息 | ≤ 上游 Steam/LAN 传输单包上限（数值以 AP-004 审计为准），超出必须分块 |
| 发送队列积压 | 任意时刻 ≤ 1 s 的发送量；持续超过 5 s 触发 F18 安全失败 |

不能只报告空场景平均 FPS；与四人基线必须在同一硬件、同一场景下对比。

## 5. 超时与重试预算（R18，提议值）

故障发生后不得临时放宽这些数值；调整需更新本文件并记录原因。

| 场景 | 预算 |
| ---- | ---- |
| 能力协商（加入后、进入正式流程前） | 10 s 内完成，否则拒绝加入并提示 |
| 场景/阶段就绪屏障 | 10 s 后显示等待提示；30 s 后给出重试/返回大厅路径 |
| 菜单操作确认 | 单次 5 s；最多重试 3 次；总上限 15 s；重发只返回已有结果 |
| 断线后等待原玩家（需本人选择的阶段） | 120 s，房主可提前选择处理方式 |
| 心跳/断线判定 | 沿用上游 `network_heartbeat.gd` 的数值（AP-004 记录） |
| Host 退出后客户端回到主菜单 | ≤ 10 s，且释放全部远程输入 |
| 同一阶段自动恢复次数 | 最多 3 次，之后停止推进并给出下一步 |
