# ADR-000：测试运行时与游戏脚本审计来源

日期：2026-10-28。状态：已采用（本机）；公共 CI 部分待定。关联：AP-002、AP-004、D-004、D-005。

## 背景

ACTION_PLAN 要求测试工具与目标 Godot 3 版本匹配，并在恢复出的目标工程中审计游戏本体。目标游戏的引擎是定制构建 `3.7.dev.custom_build.74e86be54`，官方没有同名的发行版本；游戏脚本以 GDScript 字节码（`.gdc`，版本 13）打包在 `Brotato.pck` 中，没有注释。

## 选择

1. **测试运行时**：把游戏自带的 `Brotato.exe` 与 `steam_api64.dll` 复制到 `.local/engine/`，以 `--no-window --path <项目> -s <脚本>` 方式运行规则测试和编译检查。副本目录没有 `Brotato.pck`，因此引擎加载的是测试工程而不是游戏。`APPDATA` 指向 `.local/userdata/<运行>`，`user://` 落在隔离目录。
2. **游戏脚本来源**：`tools/recovery/` 中的脚本从 PCK 提取文件并把 `.gdc` 还原成 `.gd`。Token 表与内置函数表直接从目标 `Brotato.exe` 读取（`pe_string_tables.py`），不是凭版本猜测。
3. **还原结果验证**：同一引擎分别加载原字节码工程与还原源码工程（自动加载用空桩代替，防止运行游戏单例），比较每个脚本的方法签名、属性、常量与信号（`validation/dump_scripts.gd`、`compare_dumps.py`）。

## 依据

- 测试运行时与目标版本逐字节一致，语法与 API 差异风险最低；不需要额外下载 Godot。
- 自行还原避免引入 GDRE Tools 下载；表来自目标二进制，映射错误会表现为语法错误，能被引擎检出。

## 验证结果（2026-10-28）

- 479 个脚本（基础 445 + DLC 35，`print_viewport` 重复）全部还原，0 失败。
- 两种工程中都能加载的 384 个脚本：方法/参数/默认值/属性类型/常量/信号**完全一致**。
- 还原工程没有任何语法级错误；其余加载失败在原字节码工程中同样出现，原因是空桩自动加载无法提供类型推断（`:=` 推断）以及编辑器专用类，与还原无关。
- 还原后的行号与原始源码一致（由字节码行表校正）。

## 代价

- 引擎副本与还原脚本是商业文件，只能放在忽略目录，不能进入仓库、CI 或安装包。
- 公共 CI 无法使用该引擎；需要另选一个 Godot 3.x 官方 headless 版本运行纯规则测试，并接受与目标版本的差异（待定，AP-022 前）。
- 约 95 个依赖自动加载类型推断的脚本只能确认“与原字节码同样失败”，不能直接证明其结构一致；审计时它们的源码仍可阅读，必要时对照字节码。
