# Runbook：M1 验证（AP-007）

对应 ACTION_PLAN 第 5 节。M1 是技术路线闸门：只有原工坊版 Brotato Online + 本扩展通过，才算路线 A 成立。

## 需要的资源

| 资源 | 数量 | 说明 |
| ---- | ---- | ---- |
| Steam 账号（各自拥有 Brotato，按 R06 拥有一致的 DLC） | 5（五人流程）；8（最终验收） | 同一账号的多个实例共享 Steam ID，Brotato Online 以它为身份，不能代替多账号 |
| Windows 电脑或虚拟机 | 5 | 每台一个客户端、一名操作者或远程控制 |
| 工坊订阅 | 每个账号都订阅 Brotato Online（3741034628） | 开发版扩展不在工坊，需在每台机器上用隔离实例侧载（见 isolated-game-instance.md），或由 OWNER 决定上传私有/隐藏测试条目 |
| 录屏 | 每台 | OBS 或系统录屏，记录完整流程 |

当前状态：本机 1 个账号、1 台机器，**步骤 3～6 BLOCKED**。

## 步骤与证据

| 步骤 | 操作 | 工具 / 自动化 | 需要记录 |
| ---- | ---- | ------------- | -------- |
| 1 | 隔离用户数据，保存游戏与上游指纹 | `tools/setup.ps1`、`tools/instance.ps1`（已完成：EV-0002、EV-0004） | 指纹、真实存档未变化 |
| 2 | 装载最小独立扩展，确认脚本链与生命周期 | `--coopplus-probe`（已完成：EV-0006） | lifecycle.json、modloader.log 摘录 |
| 3 | 4→5 人：记录每台机器的成员、稳定槽位、当前索引、虚拟动作、RunData 人数；检查设备唯一与本机归属 | 扩展的诊断导出（AP-006 实现后提供 `--coopplus-diag`） | 每台机器的槽位表截图/导出 |
| 4 | 每名玩家选不同、可识别的角色与武器；战斗中各自移动/攻击；一次升级/箱子、一次商店购买；进入下一波 | 人工操作 + 录屏 | 录像、Host 与 Client 日志 |
| 5 | 在每个提交边界对照 Host/Client 的 roster、人数、装备、经济结果；确认场景保护没有裁掉 P5 | 诊断导出比较（AP-008 规则 + AP-006 适配） | 对照表 |
| 6 | 8 个逻辑槽位逐通道输入；8 个独立 LAN 实例最小开局并切换一次菜单 | 规则测试（已覆盖 8 槽位分配，见 tests/unit/core）+ 实机；同账号 LAN 的身份冲突需先解决 | 槽位池使用情况 |
| 7 | 回到 1～4 人验证开局和退出；再次比较上游指纹 | `tools/setup.ps1` 重新核对 | 指纹前后对比 |

## M1 报告必须回答

1. 独立补丁是否成立（原工坊文件指纹前后一致）。
2. 覆盖了哪些内部方法（列表引用 limits-audit 与 ADR-001）。
3. 初始化是否可靠（回调次数、退出/重入）。
4. 八人输入是否足够（虚拟设备方案与实测）。
5. 仍未验证的功能。

每次失败保留最小复现。AP-005/AP-006 在约定时间盒内拿不到新证据时，收敛为阻塞报告并列出所需上游接口，不转为定制联机分支。
